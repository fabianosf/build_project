```alphalang

  foundational_principles: {
    principle_1: "Falhas parciais são a norma, não a exceção, em sistemas distribuídos",

    principle_3: "Redundância sem isolamento de falha não é resiliência",

    principle_5: "O sistema mais resiliente é o que você testa quebrando de propósito"
  },

  practical_patterns: {
    circuit_breaker: "Interrompe chamadas a um serviço já degradado antes de piorar",
    retry_with_backoff: "Retentativas com backoff exponencial e jitter",
    bulkhead: "Isolamento de recursos para evitar falha em cascata",
    timeout_budget: "Orçamento de tempo por requisição em toda a cadeia de chamadas",
    graceful_degradation: "Funcionalidade reduzida em vez de falha total",
    chaos_engineering: "Injeção controlada de falhas para validar suposições"
  },

  sre_fundamentals: [
    "SLIs, SLOs e error budgets como linguagem entre eng e negócio",
    "Toil como métrica a ser reduzida sistematicamente",
    "Postmortems sem culpa (blameless) como ferramenta de aprendizado",
    "On-call sustentável como requisito de design, não acidente"
  ]
}
```

**O que este bloco ensina:** Fundamento teórico de por que sistemas distribuídos falham e como projetar para tolerar isso, em vez de tentar (inutilmente) evitar toda falha.
